# Проверка заменённых форм — 21 октября 2026

Проверка локальной копии, без отправки заявок в CRM и без изменения обработчиков.

## Подтверждено

- Открытая нижняя форма главной использует исходный чанк form_footer, попап — form_tpl1 из footer_new
- Оба вызова используют FormIt и hooks=FormItSaveForm,roistat_hooks; обязательные серверные поля fio и phone сохранены
- В HTML обеих форм присутствуют ajax_form, отдельный af_action длиной 32 символа, csrf_token длиной 64 символа и штатные служебные поля
- Скрипты jQuery, AjaxForm и home_solution доступны по HTTP 200; синтаксическая проверка последних двух проходит
- После удаления расширенной формы нет зависимостей от scenario, object и deadline в действующем обработчике главной
- Исходный roistat_hooks.php исполнен офлайн с подменой единственного file_get_contents на захват сформированного запроса в памяти. Имя, телефон, страница и причина обращения сопоставлены правильно; ключ интеграции присутствует. Заявки наружу не отправлялись
- Из локального PHP доступно TLS-соединение cloud.roistat.com:443; allow_url_fopen включён. Это проверка связи, а не проверка авторизации или доставки лида
- Состав нижних форм ранее сопоставлен на 54 адресах: 47 адресов с формами, 6 без форм, один с исходной 403 на обеих версиях. Это не функциональный тест отправки с каждого адреса

## Существующее ограничение

Цепочка интеграции: AjaxForm → FormIt → FormItSaveForm → roistat_hooks → Roistat → CRM. Текущий PHP-хук выполняет запрос leads/add, не анализирует ответ API и возвращает true. Успех интерфейса или запись в FormIt не доказывают получение заявки Битрикс24. Это существующая логика, не изменение при замене формы.

Доступ к настройкам интеграции Roistat и журналу входящих заявок Битрикс24 в рамках проверки не использовался. Приём заявки, маршрутизация, проверка дублей и создание сущности CRM не подтверждены.

## Вывод

Нарушений конфигурации отправки, вызванных заменой форм, не выявлено. Сквозная доставка не подтверждена: для этого требуется согласованная тестовая отправка с маркировкой «ТЕСТ» отдельно из нижней формы и попапа, затем проверка соответствующих записей в Roistat и Битрикс24. Повторять отправку без проверки дублей нельзя.

Диагностические утилиты находятся только в игнорируемом _backups и /tmp локального контейнера; публичных тестовых обработчиков не создано. Рабочие обработчики и настройки защиты не изменялись.
