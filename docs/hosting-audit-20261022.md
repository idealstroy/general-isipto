## Проверка релиза и форм

Все 7 файлов payload совпадают с manifest и рабочими файлами. Все 17 прямо подключённых общих ресурсов шаблона найдены на хостинге и совпали по SHA256. Требуемые чанки, сниппеты, TV, формы и Roistat-хук совпадают с хостингом.

Проведена отдельная миграция свежей копии БД через MODX API: создание статического шаблона и чанка, копирование всех 11 TV-связей исходного шаблона и переключение только главной. Проверка прошла на PHP 7.3.33. ID нового чанка в тестовой БД оказался 133, а в рабочей локальной версии — 134: это подтверждает необходимость регистрации по именам и связям, без жёсткого использования локальных ID.

В изолированном PHP 7.3.33:

- preflight: `errors: []`, 7 файлов payload проверены;
- новая главная, исходная страница ведения ИД и управления строительством сформированы с HTTP 200;
- один H1 на главной, присутствует новый блок автоматизации, нераскрытых MODX-тегов и фатальных PHP-ошибок в ответах нет;
- штатный `#form_up` присутствует в одном экземпляре; попап и нижняя форма содержат служебные значения AjaxForm длиной 32 символа;
- исходный HTML попапа и подключение `AjaxForm.initialize` сопоставлены с действующим доменом. PHP DOMDocument перемещал последнее скрытое поле при разборе; проверка исходных границ формы подтвердила поле и на домене, и в тесте. Изменение формы не потребовалось;
- реальных отправок заявок не выполнялось. Внешняя сеть тестового проекта была отключена.

Тот же рендер и preflight прошли на PHP 7.4.33. На PHP 5.6 прошли работа MODX API и preflight, но HTTP-рендер остановился на существующем `??` в исходном index.php; совместимость всего сайта с 5.6 не заявляется.

Изолированный тест повторяет версию PHP веб-ответа и ветку MySQL 5.7. Сборка MySQL Beget, Apache и дистрибутив хостинга полностью не воспроизводились: тест использовал встроенный HTTP-сервер PHP с эмуляцией HTTPS-параметров обратного прокси. Рабочие общие Apache-настройки на хостинге этим релизом не заменяются.

В журнале теста исходных страниц встречались сообщения MODX о `getResources` и `[+output`; общие элементы не изменялись. В этом аудите они не исправлялись. Проверка рендера не означает отсутствие любых прежних ошибок всего сайта.

Доставка до Битрикс24 пока не доказана. Существующий `roistat_hooks` не проверяет ответ API Roistat; сообщение об успехе само по себе не подтверждает создание записи CRM. Для закрытия этого пункта нужны разрешённые контрольные отправки попапа и нижней формы и подтверждение записей в CRM. Хук в этой проверке не изменялся.
