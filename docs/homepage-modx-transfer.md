# Перенос обновлённой главной в локальный MODX

Выполнен 20 октября 2026 года. Публичный сайт https://isipto.ru/ не изменялся.

## Где хранится новая главная

- Адрес: http://localhost:3000/
- Ресурс: 3075, контекст web; site_start и URL не менялись
- Новый статический шаблон MODX: 84, «Главная — управляемая служба ПТО»
- Файл шаблона: modx-isipto/assets/templates/home_solution.html
- Исходный общий шаблон 33 и assets/templates/index_new.html сохранены; региональные главные продолжают использовать их
- H1, Title, Description, canonical, OG и региональные настройки остались в исходных TV/настройках ресурса и общих чанках
- Обновлена служебная дата editedon главной для штатного LastModified

Контент хранится по существующей модели сайта: запись шаблона MODX и его связи с TV — в MySQL, редактируемая разметка — в статическом HTML-файле. Не установлен PHP-перехват главной и не заменён корневой index.php.

## Файлы и динамические зависимости

- Нижняя открытая форма использует исходный общий чанк form_footer, как на домене; изолированный home_solution_form удалён после проверки отсутствия ссылок
- assets/templates/home_solution_review.html — отдельный статический чанк home_solution_review, использующий исходные изображения из TV docs
- assets/css/home_solution.css — прокрутка к якорям и учёт reduced-motion; стили удалённых полей очищены, общие стили сайта не изменены
- assets/js/home_solution.js — плавное переключение штатного хэдера; обработчик удалённой расширенной формы очищен
- Исходные header_new/footer_new, our_projects, getImageList, pdoResources, AjaxForm/FormIt используются штатно
- Согласие, CAPTCHA, honeypots, FormItSaveForm и roistat_hooks сохранены; отправка в CRM/почту при проверках не выполнялась
- Используемые новые изображения: images/preview-pto-automation-clean.png, images/preview-pto-management-red.png, images/pto-managed-result-v2.png

Конверсионные кнопки открывают штатный попап #form_up из общего footer_new с исходной формой form_tpl1 через Fancybox — как на домене. Нижний самостоятельный блок #solution-calculation использует исходную открытую форму form_footer с именем, телефоном, согласием и кнопкой «Заказать звонок». Кнопки-ссылки и специализированный опрос не изменены. Тестовый JS с имитацией отправки на главную не подключается.

После проверки переноса тестовый URL /_preview/isi-solution/ удалён по поручению владельца. Каталог _preview, изолированный сборщик и зафиксированный источник source-home.php больше не нужны главной и удалены из рабочей части проекта. Их копии остались только в игнорируемом бэкапе.

## Безопасность и проверки

1. Определены ресурс, общий шаблон, TV и динамические чанки
2. Сохранён полный дамп БД, файлы и исходная отрисовка; _backups исключён из Git
3. Подготовлен отдельный статический шаблон без изменения общего шаблона
4. Сохранены ссылки, подключены отдельные штатные чанки формы и отзывов
5. Новая версия назначена только главному ресурсу; прочие настройки сохранены
6. Кэш очищен через MODX cacheManager от имени www-data; выполнены HTTP, ссылочные и браузерные проверки
7. Быстрый откат фактически проверен, после чего новая версия возвращена на главную

Проверены 37 адресов: у остальных 36 не изменились HTTP-статусы, Title и H1–H3. Среди них есть исходная 403 на /vedenie-id/; это существующая коллизия физического каталога с friendly URL, не исправляемая данным переносом. В новом контенте сохранена рабочая ссылка /index.php?q=vedenie-id/.

Сохранены 26 уникальных ссылок утверждённого основного контента; 28 подключаемых файлов доступны; неразрешённых тегов MODX нет. Проекты имеют один комплект штатных элементов «Смотреть ещё», отзывы и блог загружаются динамически. Проверены настольный и мобильный режимы, открытие и закрытие Fancybox, согласие, наличие защитных полей, мобильное меню, закрепление хэдера. Реальная доставка заявки и вход в админку под пользователем не проверялись.

Сравнение всех 2860 ресурсов подтверждает изменения только у 3075: template и служебная editedon. Исходные файлы index.php, .htaccess и index_new.html не изменены.

## Резервная копия и откат

Папка: _backups/homepage-before-modx-transfer-20261020/. В ней database.sql.gz, исходные файлы, resource-before.json, preview/, исходная отрисовка, SHA256-манифест, отчёт проверок и инструкция отката.

Быстрый откат выполняется штатным сохранением ресурса через MODX API:

```powershell
Set-Location -LiteralPath 'C:\Users\marke\isipto-main\modx-isipto'
docker cp 'C:\Users\marke\isipto-main\_backups\homepage-before-modx-transfer-20261020\rollback-homepage.php' modx-isipto-web-1:/tmp/rollback-homepage.php
docker compose exec -T --user www-data web php /tmp/rollback-homepage.php
```

Он возвращает шаблон 33 только главной и обновляет кэш и LastModified. Утилита находится только в бэкапе вне web-каталога; подготовительные инструменты .migration/safe-home-migration.php, home-transfer-check.mjs и qa-isi-preview.js удалены из рабочей части после завершения переноса. Исходные общие шаблоны и данные не удалялись. Восстановление всей БД из дампа — отдельная операция, которая отменит и более поздние изменения; автоматически её выполнять нельзя.

Тестовый URL, preview.js и source-home.php возвращают HTTP 404. Главная возвращает 200. После очистки повторно проверены все 37 контрольных адресов, 26 ссылок утверждённого контента и 28 подключаемых файлов: новых ошибок нет. В рабочих шаблонах, CSS и JS нет подключений удалённого тестового кода.

Три изображения с именами preview-pto-automation-clean.png, preview-pto-management-red.png и pto-managed-result-v2.png не являются остатками: они используются основной главной и сохранены. Общие элементы MODX, исходный шаблон региональных главных, база данных и остальные страницы не удалялись.

## Будущее развёртывание на домене

Изменения MySQL не попадают в Git автоматически. Для публикации понадобится перенести перечисленные файлы, зарегистрировать один статический чанк home_solution_review и новый статический шаблон, скопировать связи TV исходного шаблона и назначить новый шаблон фактическому главному ресурсу. Штатная форма form_footer уже существует на сайте; отдельный чанк формы больше не нужен. Локальный номер 84 не следует слепо переносить в рабочую БД: на сервере он может быть занят.

Перед публикацией нужен отдельный бэкап хостинга и повторная проверка его ресурсов и окружения. Не заменять рабочую БД целиком локальным дампом, не переносить Docker-конфигурацию, локальные настройки подключения, preview или служебные файлы .migration. После подключения проверить реальную доставку формы контролируемой заявкой с разрешения владельца.

Финальная сборка описана в deployment/homepage/README.md; повторяемая команда — scripts/build-homepage-release.ps1. Пакеты и контрольные суммы создаются в игнорируемом dist/. Внутри только 7 файлов payload, спецификация элементов MODX, манифест SHA256, отчёт локальных HTTP-проверок, CLI-only preflight и инструкция безопасной установки/отката. Автоматической активации на домене нет.
