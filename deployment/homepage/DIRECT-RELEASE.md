# Обновление форм — прямой Битрикс24

Это точечный пакет обновления уже опубликованного сайта, НЕ полный архив и НЕ импорт БД. Хостинг этой подготовкой не меняется. Старый build-homepage-release.ps1 и production-deploy.php для этого обновления не использовать.

Порядок после отдельного разрешения на публикацию:

1. Снять и проверить свежие резервные копии файлов и БД хостинга. Согласовать контроль обеих форм до появления записей CRM.
2. Распаковать пакет вне public_html, владельцем сайта, не root. Выбрать фактический веб-PHP хостинга (ранее 7.3.33), не системный PHP 5.6.
3. Настроить секрет вне публичной папки: `<родитель public_html>/.isipto-secrets/bitrix24.env`, каталог 0700, файл 0600, владелец — пользователь сайта. Внутри одна строка BITRIX24_WEBHOOK_URL=... . Не класть .env в payload/public_html и не передавать вебхук через аргументы командной строки или журналы. CLI configure-direct-secret.php принимает адрес через stdin; --check ничего не меняет. Если PHP сайта работает другим пользователем, согласовать минимальный групповой доступ с хостингом, не открывать доступ всем.
4. Выполнить `php7.3 deploy-direct.php inspect /absolute/public_html`. Команда только читает файлы, БД и доступность секрета. Любые неизвестные отличия блокируют apply; не расширять разрешённые хэши без анализа.
5. После разрешения выполнить `php7.3 deploy-direct.php apply /absolute/public_html`. Сначала создаётся точечный приватный бэкап и журнал, затем файлы и элементы MODX обновляются по именам. Номера локальных элементов не используются; ресурсы, TV и рабочие заявки не импортируются и не переназначаются. Статические элементы получают файловый источник с базой в корне сайта. Не возвращать source=0 для CRM-сниппета.
6. Проверить HTTP, главную и специальные формы. С согласованными тестовыми данными отправить попап и нижнюю форму, подтвердить ID, отдел, ответственного и отсутствие дублей в CRM. Успех интерфейса/страница Спасибо не заменяют подтверждение CRM. BIM/обучение отдельно проверить с владельцами направления.
7. При сбое выполнить `php7.3 deploy-direct.php rollback /absolute/public_html`. Восстанавливаются только затронутые файлы и элементы; новые заявки и остальная БД сохраняются. Если после релиза кто-то менял эти файлы/элементы, автоматический откат откажется, потребуется сверка журнала. Возврат одного шаблона главной не откатывает общие обработчики.

Маршруты: ПТО — 31 / C31:NEW / 3280; BIM — 99 / C99:NEW / 715; обучение — 99 / C99:NEW / 193; квиз — 31 / C31:NEW / 25 (сохранён ответственный прежнего PHP-квиза). amoCRM и неиспользуемые endpoints со старой отсутствующей воронкой 57 удалены. Аналитика Roistat сохранена; старые имена hooks/два URL оставлены только как переходники без Roistat API и ключей. Для старых открытых не-Ajax форм может потребоваться обновление страницы из-за обязательного CSRF-токена.

Секрет и его права необходимо проверить фактически на хостинге. Локальные тесты не подтверждают сетевой доступ и права вебхука от имени веб-PHP хостинга. До сквозной проверки публикация не считается завершённой.
